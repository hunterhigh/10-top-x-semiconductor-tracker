# 10V Dashboard 后端与正式渲染器交接

## 1. 交接目标

把现有数据管线接到已定稿的 `01-final-ui/10-market-voices-complete.html`，由确定性程序生成与定稿 UI 一致的单 HTML。UI 文件是视觉和交互真源，但其中演示数据不是生产数据。

后端同事需要完成两类工作：

1. 适配工作：现有后端已有数据，但字段、窗口或渲染结构与新 UI 不一致，需要修改。
2. 补齐工作：新 UI 依赖的派生字段、股票下钻统计、周报变化榜单等若尚未生成，需要新增。

## 2. 当前已有能力与主要差距

### 已有

- 每只股票一个结构化文档，包含 `instrument`、`mentions[]`、`price_series`、`price_status`。
- 每条 mention 已包含 `tweet_id`、`blogger_id`、ET 日期、`stance`、`mention_type`、`reasons[]`、`text`、`url` 等字段。
- 10 人配置及 `signal_type` 角色划分。
- 日/周主分类、周变化分类、月度内部标签、人物一致度、人物每日去重股票清单的确定性函数与测试。

### 必须修改或补齐

- 旧正式渲染器仍输出旧页面，必须建立面向定稿 HTML 的新渲染入口，不能继续把旧 HTML 当生产模板。
- 所有报告窗口统一为当日、滚动 7 日、滚动 28 日；删除季度/90 日主报告逻辑。
- 新增或落地本合同中的完整 render payload，尤其是周报三个变化榜单、月报排序字段、股票下钻的 10 人窗口状态和 28 天人物统计。
- 生产 HTML 必须把头像和股票下钻页一起内嵌，所有股票入口使用 `#stock=<symbol>`。
- 当前 `build_db.py` 使用固定 UTC-4 模拟 ET；应改为 DST-aware `America/New_York`，并保证建库与渲染使用同一时区实现，避免冬令时日期错位。
- `reasons[]` 为空时不得由渲染器或 LLM 编造理由。UI 显示“暂无结构化理由”或隐藏理由区域，但仍可展示原始证据。
- 未接入或不可用价格不得显示 0%：必须输出明确状态并显示“暂无行情数据”。

## 3. 数据角色边界

追踪 10 个账号，但观点共识分母不是 10：

- 7 个 `signal_type=opinion`：只有 `mention_type=explicit_stance` 且 `stance` 为 `bullish/bearish/neutral` 的记录进入观点方向计算。
- `flow/news/disclosure`：可在人物卡、个人视角和证据区展示对应的结构化方向信号，但不得计入“观点账号共同看多/看空”的人数，也不得描述为其个人持仓或观点。

如果产品未来决定把独立信号源纳入主共识，必须先修改规则文档、规则脚本和测试，不能只改前端数字。

## 4. 源数据最低字段

| `bio` | 建议 | 卡片人物简介 |

### 每条结构化 mention

| 字段 | 必需 | 规则 |
|---|---:|---|
| `tweet_id` | 是 | URL 缺失时的去重后备键 |

## 5. 时间窗口

报告截止日 `D` 按 America/New_York 日历日解释，闭区间：

- 日报：`[D, D]`
- 周报：`[D-6, D]`
- 周报对比前窗：`[D-13, D-7]`
- 月报：`[D-27, D]`，固定 28 个日历日，不是自然月
- 股票下钻价格图：覆盖约 28 天，实际交易日按可用价格序列展示
- 股票下钻共享统计窗口：今日、最近 7 日、最近 28 日；同时驱动概览、人物立场、人物统计表及窗口涨跌幅

## 6. 页面级派生字段

完整字段结构见 `dashboard-render-contract.schema.json`。以下是不可缺少的计算口径。

### 6.1 一级人物卡

- 当日按“账号 + 股票”聚合。
- 同账号、同日、同股、同方向多帖只算一只股票。
- 同股当日同时有 bullish 和 bearish，分别进入两侧。
- neutral 只包括没有任何 bullish/bearish 的股票，但一级卡不展示 neutral。
- 一级卡仅显示 bullish 前 3、bearish 前 3；溢出数为 `total - 3`。
- 股票代码可点击进入 `#stock=<display_code>`。
- 整卡点击打开个人视角；“X 主页”标签只打开人物外链，不能同时打开侧栏。
- 个人视角仍展示全部股票、全部相关结构化记录、`reasons[]`和原帖。

### 6.2 日报与周报主栏目

每股最多进入一个栏目，优先级：

1. 同时至少 1 个看多观点账号和 1 个看空观点账号：`disagreement`。
2. 无看空观点账号且至少 2 个不同观点账号看多：`shared_bullish`。
3. 无看多观点账号且至少 2 个不同观点账号看空：`shared_bearish`。
4. 其余不进入主栏目。

无方向账号不阻断共同方向。栏目顺序固定为明确共同看多、明确共同看空、存在多空分歧。不得恢复 `other_notable`。

股票卡需要：股票身份、窗口涨跌及状态、看多/看空/无方向账号、去重原帖数、有限人物行、每行 `reasons[]`、对应原帖 URL。

### 6.3 周报变化榜单

对比前 7 日与当前 7 日，每股最多进入一个榜单：

- `new_multi_bullish`
- `consensus_strength`
- `reversal_or_disagreement`

准确优先级、阈值和 tie-break 必须调用 `report_rules.classify_weekly_change()`。每个方向都要输出 previous/current 人物集合和 `retained/added/removed` 状态。`removed` 只表示当前窗口没有同方向信号，不代表反转。

### 6.4 月报

可见列固定为：股票、立场占比、涨跌幅、提及次数、看多次数、看空次数、无方向、参与账号、详情。

- `bull_share = bullish_count / (bullish_count + bearish_count)`
- `bear_share = bearish_count / (bullish_count + bearish_count)`
- neutral 不进入比例分母。
- 提及次数按唯一原帖 URL 去重；URL 缺失才使用 tweet_id。
- 参与账号为 28 天窗口内出现过相关记录的不同账号。
- 涨跌、提及、看多、看空、无方向、多方%、空方%都要提供原始数值供前端排序。
- `monthly_consensus_label` 可内部保留，但 UI 不显示该列。

### 6.5 股票下钻

必须为每只 UI 可点击股票生成：

- 约 28 天价格序列和窗口涨跌；无行情时明确状态。
- 首次打开默认选中“今日”；用户可切换最近7日或最近28日。概览数字、人物立场分布、10人统计表、展开证据和醒目的窗口涨跌幅必须共用同一个 `selected_window` 并一起更新。固定约28天价格折线不随统计窗口改变。
- 有 mention 的日期生成聚合圆点；圆点内按当天列出人物、结构化立场、`reasons[]`、原帖 URL。
- 今日/7日/28日的 10 人互斥状态：仅看多、仅看空、多空均有、无方向、未提及；五类人数之和必须等于 10。
- 人物表列为：人物、所选窗口提及、立场构成、立场一致度、最近观点与理由、展开全部；三种窗口分别由对应窗口内记录聚合。
- 立场构成显示顺序固定：看多、无方向、看空。
- 一致度=`max(bull,bear)/(bull+bear)`，neutral 不进入分母；无方向为 `— / 无方向信号`。
- 最近记录按 `created_at`，缺失时使用 date + 稳定 tie-break。
- “最近观点”只显示所选窗口中最新一条记录的 `bullish/bearish/neutral`；“多空均有”只能用于窗口累计状态，不得显示为最近观点。
- 只有相邻的有效方向记录发生 bullish↔bearish 变化时才显示反转。
- 展开全部只显示所选窗口内的日期、结构化立场、原始 `text` 和同一 mention 的 URL。
- 禁止生成“信号后5日表现”、收益、命中率、持仓或买卖推断。

## 7. 单 HTML 渲染要求

- 唯一输出为一个完整 HTML。
- 头像全部转成 `data:image/...;base64`。
- 股票下钻模板和每股数据内嵌在同一 HTML。
- 股票入口统一为 `#stock=<URL encoded display_code>`。
- 人物侧栏、报告导航、下钻打开、浏览器返回和原滚动位置恢复必须在单文件内完成。
- X 主页和原帖保留外部 HTTPS 链接并使用 `rel=noopener`。
- 正式生成时替换演示数据，不要手工覆盖定稿 CSS/DOM 结构。
- HTML 输出前对文本、理由、名称、URL 属性进行正确转义，禁止直接拼接未转义原帖文本。
- 所有列表使用稳定排序，确保同一输入生成字节稳定或至少视觉稳定的结果。

## 8. 实施优先级

### P0：交付前必须完成

- 新正式渲染器接入定稿单 HTML。
- 所有窗口和主分类规则对齐。
- render payload 全字段生成并通过 schema 校验。
- 人物卡、个人侧栏、日报、周报、月报、股票下钻全部使用真实结构化数据。
- reasons/text/url 同源绑定。
- 角色隔离：独立信号源不进入观点共识人数。
- 行情缺失状态正确，不显示假 0%。
- 单 HTML 内嵌与内部路由完成。
- 规则测试、schema 校验、HTML 脚本检查通过。

### P1：强烈建议同时完成

- ET 改为 DST-aware 并补边界测试。
- 增加快照测试：固定小数据集生成 HTML 后检查关键栏目、数字和链接。
- 增加数据不变量检查：五类人物状态合计=10、栏目互斥、URL 去重、reasons 同源。
- 生成 SHA256 和构建元信息，便于确认线上文件来自哪次数据快照。
